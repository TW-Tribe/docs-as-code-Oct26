# Docs as Code Starter (Docusaurus)

A ready-to-use starter for corporate documentation: Docusaurus site, Markdown linting,
pull request checks, code owners, and automated publishing with GitHub Actions.

## Quick start

```bash
npm install
npm run init -- <github-org> <repo-name> "<Site Name>"   # replace placeholders once
npm start                                                  # http://localhost:3000/<repo-name>/
```

Before every pull request:

```bash
npm run check    # lint + production build
```

## What is in the box

| Path | Purpose |
|---|---|
| `docusaurus.config.js` | Site settings: title, `url`, `baseUrl`, navbar, footer, edit links |
| `sidebars.js` | Navigation (autogenerated from folders) |
| `docs/` | Documentation content (Markdown and MDX) |
| `src/css/custom.css` | Brand colors and global styles |
| `src/pages/` | Custom pages such as the landing page |
| `src/components/` | Reusable React components for MDX pages |
| `src/theme/` | Swizzled (overridden) theme components |
| `static/` | Files copied as-is: images, `robots.txt`, standalone HTML |
| `.github/workflows/pr-check.yml` | Lint, build, and link check on every pull request |
| `.github/workflows/deploy.yml` | Deploy to GitHub Pages on merge to `main` |
| `.github/workflows/deploy-company-server.yml.example` | Alternative: deploy to your company server |
| `.github/CODEOWNERS` | Required reviewers by path |
| `.github/pull_request_template.md` | Pull request checklist |
| `.github/dependabot.yml` | Automatic dependency update pull requests |
| `.github/ISSUE_TEMPLATE/` | Documentation request form |
| `.markdownlint-cli2.jsonc` | Markdown lint rules |
| `.vale.ini` | Prose style checks (optional) |
| `.editorconfig`, `.nvmrc`, `.vscode/` | Consistent editor and Node setup |
| `STYLE_GUIDE.md`, `CONTRIBUTING.md` | Writing and workflow standards |

## Publish to GitHub Pages

1. Push this repository to GitHub.
2. Go to **Settings > Pages** and set **Source** to **GitHub Actions**.
3. Merge to `main`. The `Deploy docs to GitHub Pages` workflow publishes the site.
4. Open `https://<org>.github.io/<repo>/`.

## Protect the main branch

In **Settings > Rules > Rulesets** (or Branches), for `main`:

- Require a pull request before merging
- Require review from Code Owners
- Require the `validate` status check to pass
- Block force pushes

## Publish to a company website instead

1. Set `DOCS_URL` and `DOCS_BASE_URL` (repository variables, or edit the defaults in `docusaurus.config.js`).
2. Rename `deploy-company-server.yml.example` to `deploy-company-server.yml` and delete `deploy.yml`.
3. Add the secrets listed at the top of that workflow.
4. Configure the web server to serve the `build/` output, with `try_files $uri $uri/ /index.html` style fallbacks as needed.

## Requirements

Node.js 20 or later, Git, and a GitHub account.
