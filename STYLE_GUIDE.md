# Style guide

## Voice and tone

- Write in the second person ("you") and the active voice.
- Use present tense. Keep sentences short.
- Say what the reader can do, then how.

## Structure

- One topic per page. Start with a one-sentence summary in `description`.
- Use sentence case for headings. Do not skip heading levels.
- Use numbered lists for steps and bullets for options.

## Formatting

- Put UI labels, file names, and commands in `code` or **bold** consistently: bold for UI labels, code for files and commands.
- Always specify the language on code blocks.
- Write descriptive link text. Never use "click here".
- Add alt text to every image.

## Terminology

- GitHub, Docusaurus, Markdown, Node.js, npm (always these spellings).
- Add new product terms to `.github/styles/config/vocabularies/Docs/accept.txt`.
